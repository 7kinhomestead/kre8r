# MirrΩr — Synthesis

**What it is:** YouTube analytics → AI coaching/strategy layer. Pulls channel health, runs a coach report, content-DNA, content-secrets, and a monthly strategy self-evaluation. Several outputs already write back to `creator-profile.json`.

## Top 3 (fix these)

**1. F2 — Coach averages include Shorts while the prompt swears they don't (HIGH, confirmed)**
`analytr.js:117` feeds `health.avg_views` (all-format, `db.js:3612`) into a prompt that at `:128` literally states *"Shorts excluded from averages"* and at `:131` presents that number as "channel average." For a 725k creator whose Shorts out-view long-form 10–100x, this inflates the baseline and makes Claude tell Jason his working long-form videos are all underperforming. The correct value — `health.longform_avg_views` — already exists, unused, at `db.js:3613`. **One-line fix, high blast radius: it's corrupting the coaching narrative.**

**2. F1 — Coach report is a creative dead-end (HIGH, confirmed)**
`focus_this_week` and `trending_topics` are MirrΩr's most actionable outputs — "make this video this week," 3 seed ideas. They render as inert divs (`mirrr.html:719-726`) with **no push affordance**, while content-secrets two rows away has a working "Save to Soul" button (`:2526`). This is a direct Secondary-Directive violation: the tool generates a concrete make-instruction, then makes Jason retype it into Id8Ωr. Add "Start in Id8Ωr →" deep-links + persist focus to `kv_store` so it survives navigation and shows on Mission Control.

**3. F3 — `best_video` is a raw analytics row, not a per-project sum (MEDIUM, confirmed)**
`db.js:3549-3557` does `ORDER BY a.metric_value DESC LIMIT 1` with no aggregation and no format filter → on YouTube this is almost always a Short. The coach prompt (`:132`) then says "Best performing video is '<Short>'" and asks Claude to coach *long-form* strategy around it — contradicting its own framing and disagreeing with the DNA/constellation views. Pair this with F2: together they mean the coach report is reasoning from two Shorts-polluted anchors at once.

*(F4–F8 are real but lower-stakes: F5/F6 are loop-quality gaps, F4 is a latent timezone/month bug, F7 a staleness gate, F8 the seven-site `node-fetch` convention violation — all confirmed in code.)*

## Verdict: Does it close the YouTube analytics loop?

**No — it closes the read half but leaks at both the write-back and the data-integrity ends.**

- **Backward loop (analytics → creative tools): partially wired, partially abandoned.** content-secrets genuinely flows into Id8Ωr's `intelligenceBlock`. But the two richest artifacts MirrΩr computes — the **coach's "make this" instruction (F1)** and the **DNA `audience_profile` of fears/beliefs/what-converts (F5)** — are generated, sometimes persisted to Soul, and then read by *nothing*. They change the profile file but not what Jason makes next. That's the loop's whole purpose, unclosed.

- **Data integrity at the front: cracked.** The coach report — the most-read screen on an analytics-review day — reasons from a Shorts-inflated average (F2) against a Shorts best-video (F3), then can feed a wrong-month, possibly-unsynced dataset into the strategy self-correction (F4/F6). A self-correcting loop learning from contaminated inputs doesn't just fail to help — it actively miscalibrates Id8Ωr.

**The closing move:** the loop becomes real with ~3 surgical changes — swap to `longform_avg_views` + aggregate `best_video` (F2/F3, restores trustworthy inputs), then add the one-click "Start in Id8Ωr →" push and inject `audience_profile` into the Id8Ωr/WritΩr prompts (F1/F5, restores the write-back). Until then MirrΩr is a high-quality dashboard that *looks* like a loop but terminates in Jason's manual retyping.

## Findings (8 total)
### [HIGH] Coach report is a creative dead-end — focus_this_week and trending_topics never reach Id8Ωr/WritΩr
**workflow-order** | src/routes/analytr.js (POST /coach, ~line 90-200); public/mirrr.html:719-724, 1220-1224
The POST /coach SSE report produces the most directly actionable outputs in MirrΩr: focus_this_week ("one concrete thing to do or make this week"), trending_topics (3 video ideas the audience would love), and on-camera performance coaching. But in public/mirrr.html these render as static text/pills (#coachFocus, #coachTopics via topic-tag spans, #coachNote) with NO button to push them anywhere. Compare to content-secrets, which has a working 'Save to Soul' button (mirrr.html:2526 → PATCH /save-secrets-to-soul → creator-profile.json content_intelligence → injected into Id8Ωr concepts at id8r.js:443 and id8r.js:622). The coach report violates the Secondary Directive directly: it generates a concrete 'make this video' instruction, then forces Jason to manually retype it into Id8Ωr. On a non-filming analytics-review day this is exactly the data-he-looks-at-but-doesn't-act-on failure mode. The trending_topics are literally seed ideas with no 'Start in Id8Ωr →' affordance.
**Fix:** Add a one-click action under focus_this_week and each trending_topic: 'Start this in Id8Ωr →' that deep-links to /id8r.html with the text prefilled as the raw idea (Id8Ωr already accepts a seed via its shape_it/find_it modes). Persist the latest coach focus to kv_store (e.g. mirrr_coach_focus) and surface it on NorthΩr/Mission Control as a pending action so it survives navigation. Also consider injecting trending_topics into the Id8Ωr intelligenceBlock the same way content_intelligence is, so the ideation tool is already aware of them.

### [HIGH] Coach report averages include Shorts while claiming to analyze long-form only
**bug** | src/routes/analytr.js POST /coach: `const avgViews = health.avg_views || 0;`
The /coach prompt sets avgViews = health.avg_views (analytr.js, from getGlobalChannelHealth().avg_views), which is the ALL-format YouTube average across every video including Shorts (db.js:3538-3548 — no format filter). The same DB call already computes longform_avg_views (db.js:3574-3583, filtered to format IN ('longform','standard')) specifically for this purpose. Meanwhile the prompt body filters the video LIST to longform/standard and even says 'Channel average is X views per video' and 'Shorts excluded from averages'. So Claude is told an average that contradicts the videos it's shown: a channel where Shorts pull 10-100x long-form views (true for a 725k-follower creator) will get a wildly inflated 'channel average', causing Claude to tell Jason his actual long-form videos are all underperforming when they aren't. This produces false negative coaching that could steer him away from working content.
**Fix:** Use health.longform_avg_views (which already exists and is Shorts-excluded) when shortsFiltered is true / for the long-form analysis: `const avgViews = health.longform_avg_views || health.avg_views || 0;`. Same average is interpolated into bestVideo comparisons and total — audit those too so the narrative the prompt presents is internally consistent.

### [MEDIUM] best_video in channel health is picked from a raw analytics row, not summed per-project — can surface a Short or a stale row
**bug** | src/db.js:3549-3557 (best query inside getGlobalChannelHealth)
getGlobalChannelHealth's best-video query (db.js:3549-3557) does `ORDER BY a.metric_value DESC LIMIT 1` over the analytics table joined to posts/projects with no aggregation and no format filter. This returns the single highest individual analytics ROW, which for YouTube is almost always a Short (Shorts dominate view counts) and ignores that a project may have multiple posts. The coach prompt then tells Jason 'Best performing video is "<Short title>"' and asks Claude to coach his long-form strategy around it — directly contradicting the long-form framing in the same prompt. It also won't match the best_video the constellation/DNA views show, creating inconsistent 'best video' across MirrΩr screens.
**Fix:** Aggregate views per project before picking the max, and exclude Shorts for the long-form-facing best_video: `SELECT pr.id, pr.title, SUM(a.metric_value) AS views FROM analytics a JOIN posts po ... WHERE a.metric_name='views' AND po.platform=? AND po.format IN ('longform','standard') AND pr.status!='archived' GROUP BY pr.id ORDER BY views DESC LIMIT 1`. Keep an all-format variant separately if a true cross-format best is needed elsewhere.

### [MEDIUM] evaluate-strategy default month uses local-time getMonth() — wrong month near boundaries and double-counts month index
**bug** | src/routes/analytr.js POST /evaluate-strategy (lastMonth/lastYear computation at top of handler)
In POST /evaluate-strategy the 'last month' default is computed as `lastMonth = now.getMonth()===0 ? 12 : now.getMonth()`. getMonth() is 0-indexed, so in June (getMonth()===5) lastMonth becomes 5 = May — correct by luck because the 0-index offset happens to equal 'previous month'. But this is fragile and undocumented; combined with getVideosByMonth padding and parseInt, it works only because two off-by-one effects cancel. More importantly it uses local server time with no timezone anchor, so a sync run in the first hours of a new month (server in a behind-UTC zone) can evaluate the wrong period. Because the result is cached to strategy_eval_<year>_<month> kv and saved onto the report, a wrong-month evaluation then feeds Id8Ωr/strategy-engine calibration with mislabeled data — the self-correcting loop learns from the wrong month.
**Fix:** Compute the previous month explicitly and unambiguously: `const d = new Date(now.getFullYear(), now.getMonth()-1, 1); evalMonth = String(d.getMonth()+1).padStart(2,'0'); evalYear = d.getFullYear();`. This handles January rollover natively and removes the index ambiguity. Add a brief comment that month strings are 1-indexed throughout to match getVideosByMonth.

### [MEDIUM] MirrΩr DNA niche/audience_profile is generated and saved to Soul but never injected into Id8Ωr or WritΩr
**improvement** | src/routes/analytr.js POST /content-dna + PATCH /creator-profile-audience; absent in src/routes/id8r.js and src/writr/claude.js
The content-dna flow (POST /content-dna) produces a rich niche_definition, content_pillars, and audience_profile (what_they_believe / what_they_fear / why_they_watch / content_that_converts) and the PATCH /creator-profile-audience endpoint writes audience_profile into creator-profile.json. But grepping id8r.js and src/writr/ shows neither tool reads audience_profile or channel_dna_profile — only content_intelligence (the secrets) and tiktok_content_patterns are consumed. So the single most strategically valuable MirrΩr artifact for steering content (the data-derived audience fears/beliefs and 'content that converts') is computed, persisted, and then ignored by every creative tool. It changes the profile file but not what Jason makes next.
**Fix:** Inject creator-profile.json audience_profile (what_they_fear, content_that_converts, why_they_watch) into the Id8Ωr concept prompt alongside the existing intelligenceBlock, and into WritΩr's prompt builders so scripts are written toward proven audience triggers. Even a 3-line block ('Audience watches because X; they fear Y; content that converts: Z') would make every concept and script audience-calibrated for near-zero token cost.

### [MEDIUM] getVideosByMonth excludes only youtube_import, but strategy evaluation needs Jason's actually-made videos — kre8r videos posted to YT via PostΩr may be misattributed or missed
**inter-tool** | src/db.js:4773-4801 getVideosByMonth; interacts with runYoutubeSyncJob in src/routes/analytr.js and evaluate-strategy
getVideosByMonth (db.js:4773) joins projects→posts on platform='youtube' and filters `pr.source != 'youtube_import'`. This is the dataset evaluate-strategy uses to judge 'what actually happened' vs what was recommended. Two issues: (1) it relies on po.posted_at being correctly set on the youtube post row — but for kre8r-origin videos the youtube post/metrics are created during youtube-sync (runYoutubeSyncJob savePost uses item.snippet.publishedAt), so a video must have been synced or it silently drops out of the month's results, making the strategy look like it 'produced nothing' and feeding a falsely low accuracy score back into Id8Ωr calibration. (2) `source != 'youtube_import'` lets through NULL source rows but the recent-projects query elsewhere (db.js:3640) uses the safer `source IS NULL OR source NOT IN (...)` form — inconsistent filtering across the two analytics paths means the coach view and the evaluation view can disagree on which videos count.
**Fix:** Make the import-exclusion filter consistent with getRecentProjectsWithAnalytics: `AND (pr.source IS NULL OR pr.source NOT IN ('youtube_import','tiktok_import',...))`. Ensure evaluate-strategy triggers (or warns if missing) a youtube-sync before evaluating, so the month's published videos have metrics — otherwise the videoBlock '(No YouTube performance data found)' path silently degrades the self-correction loop into noise.

### [LOW] content-secrets refresh gate can permanently lock if longform count plateaus, with force only reachable from one UI path
**bug** | src/routes/analytr.js POST /content-secrets (refresh gate: `longformCount < lastCount + 10`)
POST /content-secrets locks regeneration unless longformCount >= lastCount + 10 (or force=true). For a weekly long-form cadence creator, that's ~10 weeks between any refresh of the 'content secrets' that feed Id8Ωr's content_intelligence. Because save-secrets-to-soul stamps next_update_at_video_count = longformCount + 10, the insights driving ideation can go stale for over two months even as TikTok/strategy signals move. The gate is a reasonable cost-control but it means MirrΩr's deepest creative input updates 5-6x/year, weakening the 'changes what he makes next' claim for the secrets specifically. There's no time-based escape hatch (e.g. 'also allow refresh if >45 days since last run').
**Fix:** Add an OR time condition to the gate: allow regeneration if 10+ new long-form videos OR it's been >45 days since channel_dna_secrets_generated_at, so insights can't ossify during a slow-publishing stretch. Surface 'next secrets refresh available in N videos OR on <date>' in the UI so the cadence is visible.

### [LOW] Three different Claude-call mechanisms in one file — raw node-fetch, callClaude, inconsistent with project convention
**simplification** | src/routes/analytr.js: /coach, /thumbnail-ab, /content-dna/graph (two-pass), /content-dna, /content-secrets
analytr.js calls Claude three incompatible ways: raw node-fetch with hand-rolled fence-stripping in /coach, /thumbnail-ab, /content-dna/graph, /content-dna, /content-secrets; vs callClaude() in /tiktok-patterns and /evaluate-strategy. CLAUDE.md mandates src/utils/claude.js 'everywhere ... never inline fetch'. Beyond the convention violation, the raw-fetch paths each re-implement the same `.replace(/^```(?:json)?\s*/i,'')...` fence strip and JSON.parse-with-catch, and hardcode model fallback 'claude-sonnet-4-6' / anthropic-version separately — five copies that will drift. This is also why prompt-caching (which CLAUDE.md/claude.js centralizes) is absent on the large repeated DNA-clustering prompts that re-send up to 50 video titles per call.
**Fix:** Route all text-completion calls through callClaude(prompt, maxTokens) (it already strips fences + parses JSON, removing the duplicated regex/parse blocks). For the image thumbnail-ab call, add a callClaudeWithImages helper to src/utils/claude.js rather than inlining. Centralizing also lets the large DNA clustering prompts benefit from prompt caching.
