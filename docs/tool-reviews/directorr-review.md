## CRITICAL

**C-1 — Coverage Mirror is structurally dead; shoot-day coverage state lives only in one phone's localStorage**
*(merges DIR-1 bug, DIR-6)*
The offline ShootDay package writes takes only to localStorage and never POSTs to `/api/shootday/:id/take`. The desktop Coverage Mirror polls `/summary` (reads the `shoot_takes` table) every 5s with a pulsing "Live" dot — over data it can never receive. During a real shoot it shows `0/N` forever. Worse, Cari's entire coverage record is unrecoverable if the phone/browser data is lost — a direct Prime Directive violation. Two reset buttons against two unsynced stores compound the loss.
**Action:** Make the offline package opportunistically POST each take when `navigator.onLine`, with a localStorage queue that drains on reconnect (PROJECT.id is already baked in). Route all resets through one code path. If sync won't ship, remove the "Live" dot and reframe as manual import — do not animate a live indicator over a feed that cannot receive data.

**C-2 — Re-running AssemblΩr silently destroys all manual take edits**
*(ED-1)*
`finalise()` calls `deleteSelectsByProject()` before inserting the fresh AI assembly. Manual "Use Checked as Sequence" edits and swapped takes live on those same rows. There's no confirm on "Run AssemblΩr" (only "Clear" confirms). Re-running after hand-curating 10 beats — even accidentally, or just to pick up one new clip — wipes everything with no undo. Prime Directive violation.
**Action:** Set a `manually_edited` flag from the two PATCH endpoints; require explicit confirm in `onBuildSelects()` when curated selects exist, and snapshot existing selects to a history row before delete. Wrap delete+insert in a single better-sqlite3 transaction (also fixes C-3 partial-read window).

## HIGH

**H-1 — No per-project concurrency guard; overlapping jobs corrupt selects and DaVinci state** *(ED-3)*
The global `jobs` Map has no per-project lock. `/selects/build`, `/davinci/build`, `/send-to-davinci` can run concurrently for one project; DaVinci can read a half-written selects set mid-delete/insert. Same class as the documented PostΩr no-overlap bug. **Action:** Per-project in-flight lock returning 409; make AssemblΩr finalise a single transaction.

**H-2 — shoot_takes records have no footage linkage** *(DIR-2 orig)*
`shoot_takes` stores `(project_id, beat_index, beat_name, status, take_number, note)` with no `footage_id`/timecode, so on-set marks can't be joined to VaultΩr clips. This is *why* C-2's dead seam exists — even if AssemblΩr wanted the judgments, there's no join key. **Action:** At minimum record a wall-clock timestamp per take upsert and reconcile against footage mtime during intake; stronger is a slate/clip-counter VaultΩr matches on.

**H-3 — Beat-index contract mismatch between ShootDay and AssemblΩr** *(IT-1)*
ShootDay prefers WritΩr `beat_map_json` and uses 1-based indices; AssemblΩr always uses PipΩr config beats and is strictly 0-based. After a script rewrite, the coverage Jason tracked maps to *different beats* than AssemblΩr assembles against — silently. **Action:** One canonical beat source + one index base (recommend a shared `getBeats(projectId)` helper); at minimum warn on WritΩr-vs-PipΩr beat-count drift.

**H-4 — shot_type vocabulary diverges across VaultΩr / DirectΩr / AssemblΩr** *(IT-2)*
DirectΩr emits `talking_head/broll/action`; AssemblΩr only matches `talking-head/dialogue`; create-project buckets as `unclassified`. A clip labeled `monologue`/`interview`/`""` yields "No talking-head clips found" and loses the whole assembly with no hint at the real cause. **Action:** Single canonical shot_type enum imported by all three; when zero match but footage exists, return the distinct shot_type values actually present (Prime Directive recovery path).

**H-5 — PATCH swap-take collapses a multi-segment sequence to one take** *(ED-2)*
`PATCH /selects/:project_id/:section_index` overwrites `selected_takes` with a one-element `[chosen]`, discarding all other segments of an assembled multi-cut beat — irreversible. The frontend caller is currently orphaned, but the live endpoint still corrupts on any call. **Action:** Remove the dead endpoint, or splice the chosen take into the existing sequence rather than overwriting.

DirectΩr's highest-signal output — Cari/Jason marking each take good/skip/needed with a note on set — is never consumed. On create-project failure it falls back to raw `project.title` (unsanitised), builds anyway, and never persists via `updateProjectDavinciState` — so it can target/duplicate the wrong Resolve project and DB/Resolve diverge silently. **Action:** Fail the job, or use the same sanitised name and persist it.

**M-4 — Hero/priority beat math off-by-one (1-based pct), duplicated in 3 places** *(merges IT-5, DIR-3, DIR-5 orig)*

Also verify the returned priority is actually attached to the beat object. **Action:** `pct = (beat.index - 1) / Math.max(1, total - 1)`; extract one shared `isHeroBeat(beat, total)`.

The two tools can resolve different interpreters → "works in AssemblΩr, fails in DirectΩr." (Editor also caches failures permanently — see M-8.) **Action:** Shared `src/utils/python.js` with one candidate order + `PYTHON_PATH`, imported by both.

**M-6 — EditΩr page overloads one screen with ~5 competing primary actions; two near-identical DaVinci buttons** *(merges DIR-5 shootday, DIR-2 improvement)*

**M-7 — DirectΩr's read-only shot list adds a decision-heavy step a solo creator can skip** *(DIR-2 improvement)*
The shot list is a formatted re-display of WritΩr-approved beats — not reorderable/annotatable. **M-10 — AssemblΩr reads per-beat fields WritΩr may not write** *(IT-3)*

**M-11 — DirectΩr hero priority never reaches AssemblΩr coverage confidence** *(DIR-3 orig)*
DirectΩr knows which beats are load-bearing (hero: catalyst/climax/hook, first 20%/last 15%); AssemblΩr flags low coverage with uniform weight. A low-coverage HERO beat — the single most dangerous gap — looks the same as low-coverage filler. **Action:** Persist hero priority onto the beat; AssemblΩr escalates "weak coverage on a HERO beat" to a blocking red warning. ## VERDICT

**What is this tool's role?** Two roles under one post-production spine, currently blurred by over-naming. **DirectΩr (shootday.js)** owns the *pre-shoot handoff*: turning approved beats into an offline, zero-dependency phone checklist for Cari and a crew brief — plus a live coverage mirror during the shoot. **EditΩr/AssemblΩr (editor.js + assemblr.js)** owns *post-shoot assembly*: matching footage to beats, building beat-mapped selects with visual/coverage confidence, and pushing to DaVinci. ReviewΩr is a thin viewer with no backend of its own.

**Is it clearly differentiated?** Partially, and unevenly. DirectΩr's **genuinely unique, no-overlap value is the offline ShootDay package** — nothing else in the pipeline produces an offline, no-wifi, partner-operated handoff, and that directly answers the 700-sq-ft outdoor reality. AssemblΩr's beat-mapped, coverage-aware assembly is also distinct and load-bearing. **But the differentiation is currently inverted and broken at the seams:** DirectΩr's prominent "live tracking" half is structurally dead (C-1) and its on-set judgments are discarded downstream (M-1), while its quiet, indispensable half (the offline package) is under-billed. Three of the highest-value findings are seam failures (beat-index base H-3, shot_type vocabulary H-4, shoot_takes dead seam M-1/H-2) where the tools speak different dialects of the same contract.

**Does it earn its place?** **Yes — but conditionally, and not in its current shape.** The post-production spine (AssemblΩr) clearly earns its place. DirectΩr earns its place *through the offline package alone*; its live-tracking surface does not yet earn its prominence and is closer to busywork until C-1, M-1, and H-2 land. The fix is not to cut DirectΩr but to **invert its emphasis** — lead with the prep handoff, make the on-set coverage data actually flow into AssemblΩr, and collapse EditΩr/AssemblΩr/ReviewΩr's redundant naming and dual DaVinci buttons (M-6, L-3) so each named surface owns one thing. Do that and the DirectΩr→AssemblΩr pair becomes the most defensible, decision-reducing part of the pipeline. Leave the seams broken and the creator is paying — in screen time, in re-decided judgments, and in lost coverage state — for capability the system already has but doesn't connect.
