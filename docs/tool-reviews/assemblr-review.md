## 5. VERDICT: What makes AssemblΩr "a mess"

Three root causes, in order of blame:

**Root cause 1 — The compound-clip assembly silently produces an empty timeline and reports success.** This is the single mechanical defect that turns the whole tool into "a mess." `build-selects.py` builds isolated per-beat timelines (BEAT_01…) and tries to stitch them into `02_SELECTS` as compound clips via `beat_tl.GetMediaPoolItem()`. When that returns None (a real DRV20/21 risk) it appends a warning and continues; when it *does* work, the duration math `int(GetClipProperty("End")) - int(GetClipProperty("Start"))` throws `ValueError` on timecode strings and is swallowed to `dur_frames=0`. Either way: `02_SELECTS` ends up empty or all clips/markers stack at frame 0, **`current_frame` never advances past 0, so every PipΩr beat marker and b-roll anchor collapses to the timeline head**, yet `run()` returns `ok:true` with `clips_placed` counting the orphan per-beat placements. The creator opens the rough cut, finds nothing or a pile-up at frame 0, and the UI told him it succeeded. (BUG-01, ASM-002/ASM-3/IT-3, ASM-008, ASM-007/ASM-4.)

**Root cause 2 — Three duplicate review surfaces and three "send" buttons, none of which the creator can tell apart.** "Push to DaVinci" and "⬡ Send to DaVinci" call the *exact same* `buildDavinciTimeline()` worker — the choice is meaningless. ReviewΩr (`reviewr.html`) re-implements the same `GET /selects` review UI that `editor.html` already has, and the "ASSEMBLY READY" banner tells the creator to "Open ReviewΩr →" to do work he can already do on the page he's on. State (swaps, sequences) lives in whichever page he happened to open. This directly violates the Secondary Directive (every duplicate is an added decision). (ASM-1, ASM-2, ASM-5, ASM-9.)

**Root cause 3 — The data contract is inconsistent across writers and one-directional.** `selected_takes` is written in three incompatible shapes (AssemblΩr with handles; swapTake raw + heavy `segments[]` array + no `level`; sequence PATCH raw, no handles), so what the creator previews ≠ what lands in Resolve. And once footage reaches Resolve, nothing comes back: manual trims are destroyed on every re-push, and AssemblΩr's authoritative coverage analysis dead-ends in the selects table — it never feeds PipΩr/WritΩr re-shoot signals. The creative thread breaks the moment the creator touches the timeline. (IT-4, BUG-07, IT-1, IT-2, ASM-009.)

In one sentence: **AssemblΩr is a sophisticated reasoning chain bolted to a fragile, one-way, silently-failing Resolve bridge that reports success when the timeline is empty — and a UI that triples every decision.**

### [HIGH] Compound-clip duration is always 0 — beat-header & PipΩr markers all collapse to frame 0
