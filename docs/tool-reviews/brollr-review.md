- **Inter-tool dead link:** `broll-bridge.importBroll()` → `import-broll.py:146,149` does `os.path.isfile(file_path)` then `ImportMedia([file_path])`. Fix: `/save-to-vault` (and ideally generation time) must stream the bytes to `D:\kre8r\intake` and store the **local** path. This is the load-bearing fix that makes BrollΩr output usable at all.

### #3 — BrollΩr's analyze ignores the coverage-gap signals that justify its existence (brollr-3, high)
analyze *does* read the script + PipΩr beats + `selects.assembly_note`, but it drops the signals that say *where coverage is actually thin*: `fire_suggestion`, `coverage_confidence`, `critique_note`. broll-bridge already proves `fire_suggestion` is the right signal (`isBrollSuggestion` keys off it). Without these, BrollΩr generates generic pretty shots instead of targeting the specific beats the assembly couldn't cover — turning a precision gap-filler into a guesser, and spending Higgsfield credits on clips the edit doesn't need. High creator impact because it's the difference between "fills my real gaps" and "makes stuff I won't use."

## WORKFLOW ORDER VERDICT

**BrollΩr belongs AFTER AssemblΩr's first pass and BEFORE ReviewΩr/ComposΩr — not before AssemblΩr, and not after Compose where it currently sits.**

Proposed nav: `VaultΩr → AssemblΩr → BrollΩr → ReviewΩr → ComposΩr → ClipsΩr`

The reviewers split slightly — some said "before AssemblΩr" (BROLL-8, brollr-2: fill the vault first), others said "after AssemblΩr / parallel" (BR-3, BR-2). The correct synthesis resolves the apparent conflict by recognizing **there are two distinct temporal roles**, and the *generate* role depends on assembly output:

- **Why not pure "before assembly":** BrollΩr's value is *targeted* generation. The signals that tell it which beats to fill — `coverage_confidence`, `fire_suggestion`, `critique_note` — only exist *after* AssemblΩr runs its first pass over the real talking-head selects. Generating before assembly means generating blind (generic shots), which is exactly the brollr-3 failure. The "fill the vault first" camp is right that the clip must land in the vault before the *timeline* needs it, but wrong that generation should precede knowing the gaps.
- **Why not "after Compose" (current):** ComposΩr/ClipsΩr already worked the assembled timeline. B-roll generated now forces a backtrack — re-import to DaVinci, re-review, re-compose. That's an added decision ("is it too late to do b-roll?"), violating the Secondary Directive.

**The mental model:** assemble selects → AssemblΩr flags coverage gaps → BrollΩr fills them (generate-or-pull-from-vault) → review the combined timeline. This also makes BrollΩr the **non-filming-day tool** Jason wants: gaps are surfaced for him at the moment they're relevant, and generation's long wall-clock polls (8-10 min/clip) fit a desk day rather than blocking a shoot day.

### The "before vs after" question is really "generate vs assign" — and both must exist
The deepest workflow finding (brollr-6, BR-5) is that there are **two disconnected b-roll systems** that never hand off:
- **BrollΩr** = GENERATE clips from script + gap signals (the "before timeline" half).
- **broll-bridge.js** (inside AssemblΩr/editor.js) = ASSIGN footage_id→section_id and import to DaVinci Track 2 (the "during assembly" half).

Today the creator generates in BrollΩr, saves to vault, then must *leave*, go to AssemblΩr, re-search the vault, and hope the new clip surfaces. The two halves answer his question together: **generation runs after the assembly gap-analysis; assignment-to-timeline runs during assembly — but nothing connects them.** The fix (brollr-6, BR-5) is to carry `section_index` from analyze → generation → footage row, and add an inline "Assign to beat → send to DaVinci" action in BrollΩr that calls the existing `/api/editor/broll/import/:project_id`. The plumbing already exists; BrollΩr just needs to call it.

## CORRECT INTEGRATION WITH VaultΩr

VaultΩr is the pivot that makes the whole loop work, and it's currently bypassed:

1. **Download to local, let the watcher ingest (BROLL-1, BR-1, BR-4).** On generation/save, stream the CDN bytes to `D:\kre8r\intake`. The existing VaultΩr watcher (depth 5) then ingests/organizes it exactly like real footage — giving a real local file, a thumbnail, and a record that survives CDN expiry. Never write to `C:\` (per profile).

2. **Let the frame-analysis queue tag it (BR-4).** A vaulted AI clip currently has `subjects=[]` and `visual_analyzed_at=NULL`, so it scores near-zero in BrollΩr's own and AssemblΩr's `scoreClip` (subject match +25 vs description-only +10). Once it's a real local file, leave `visual_analyzed_at` NULL so the frame-analysis queue picks it up and tags real subjects — OR cheaply seed `subjects` from the moment's `vault_search_terms` (the vocabulary that justified generating it is the ideal vocabulary for finding it again). Either way, **a clip BrollΩr made to fill a gap becomes first-class discoverable** by the next vault search.

3. **Vault-first, generate-second default (BR-6).** For an outdoor homesteader whose vault *is* the homestead, auto-run `/vault-search` when moment cards render (it's free, no API cost) and show matches inline above the Generate button. Default = "use what you already shot"; AI generation is the explicit fallback when the vault has no match. This saves credits and keeps content authentic.

4. **Unify the duplicated match logic (brollr-9).** `scoreClip`/tokenize/b-roll-filter are reimplemented in both `brollr.js` and `broll-bridge.js` and have *already drifted* (slice 5 vs 60, different tie-breaks). Extract to `src/vault/broll-match.js` so BrollΩr and AssemblΩr surface the **same** clips for the same query — otherwise the creator sees different "available" footage in the two tools.

**Net VaultΩr contract:** BrollΩr generates → downloads to `D:\kre8r\intake` → watcher ingests → frame-analysis tags → clip is a first-class vault citizen that AssemblΩr's broll-bridge can assign to a beat and import to DaVinci. Today that chain is broken at step one (no download), which cascades into every inter-tool finding.
